Объединённые модульные задания
4 модуля — 4 последовательных задания одного web-проекта
Общая логика: студент на протяжении семестра развивает один проект. Каждый модуль продолжает предыдущий: от статического интерфейса на HTML/CSS/JavaScript к полноценному Django-приложению с шаблонами, формами, ORM, админ-панелью, медиафайлами и API.
тема проекта: «Онлайн-библиотека»
Модуль 1. Frontend-прототип: HTML + CSS + JavaScript
Период: недели 1–4. Цель — спроектировать внешний вид будущего web-приложения и создать работающий статический прототип.
Что необходимо выполнить
1.	Выбрать тему проекта и подобрать референс/дизайн. Кратко описать назначение сайта и целевую аудиторию.
2.	Создать структуру минимум из 3 связанных HTML-страниц, например: главная, каталог, страница элемента/контакты.
3.	Использовать семантические HTML5-элементы: header, nav, main, section/article, footer.
4.	Разработать единый CSS-дизайн: типографика, сетка, кнопки, карточки, состояния наведения, адаптивность минимум для desktop и mobile.
5.	Добавить JavaScript-интерактивность минимум в двух местах: меню, фильтр, модальное окно, переключатель темы, валидация, динамический список или аналогичная функция.
6.	Организовать файлы проекта по папкам (css, js, images/assets) и проверить отсутствие битых ссылок.
Результат модуля
•	Готовый статический frontend-прототип будущего Django-проекта.
•	Связанные страницы с единым визуальным стилем.
•	Работающий JavaScript без критических ошибок в консоли браузера.
Что сдаёт студент
•	Папку проекта или ссылку на Git-репозиторий.
•	Короткий README: тема проекта, структура страниц, реализованные функции JavaScript.
•	2–4 скриншота интерфейса.
Минимальная проверка работоспособности
•	Все страницы открываются и связаны навигацией.
•	CSS подключён корректно, страница адаптируется под узкий экран.
•	JavaScript-функции воспроизводятся при демонстрации.
Модуль 2. Переход на Django: проект, приложения и шаблоны
Период: недели 5–8. Цель — перенести статический прототип в Django и построить правильную серверную структуру с DTL-шаблонами.
Что необходимо выполнить
7.	Создать Django-проект и минимум одно прикладное приложение.
8.	Настроить URL-маршруты проекта и приложения; для основных страниц использовать отдельные views.
9.	Перенести HTML-прототип из модуля 1 в Django Templates.
10.	Создать базовый шаблон base.html и применить наследование шаблонов через extends/block.
11.	Вынести повторяющиеся элементы интерфейса (header, navigation, footer) в общую структуру или include-шаблоны.
12.	Подключить статические файлы CSS/JavaScript/изображения через механизм static.
13.	Сформировать минимум одну страницу со списком тестовых данных, передаваемых из view в шаблон через context.
14.	Сохранить работоспособность адаптивного дизайна и JavaScript из модуля 1.
Результат модуля
•	Работающий Django-сайт, визуально продолжающий прототип модуля 1.
•	Использование DTL, наследования шаблонов и маршрутизации.
•	Структурированный проект без дублирования основных частей HTML.
Что сдаёт студент
•	Исходный код Django-проекта или ссылку на репозиторий.
•	README с командами установки и запуска.
•	Скриншоты минимум двух страниц, открытых через Django server.
Минимальная проверка работоспособности
•	Команда python manage.py runserver запускает проект без ошибок.
•	Основные URL открываются и возвращают корректные шаблоны.
•	CSS/JS загружаются через static, а не через случайные локальные пути.
Модуль 3. Данные и пользовательский ввод: Forms + ORM + Admin + Media
Период: недели 9–12. Цель — превратить сайт в web-приложение, которое хранит данные, принимает пользовательский ввод и управляется через Django ORM и административную панель.
Что необходимо выполнить
15.	Спроектировать минимум 2 связанные модели данных. Для онлайн-библиотеки это могут быть Book и Author/Category.
16.	Создать и применить миграции; заполнить базу тестовыми данными.
17.	Реализовать вывод списка объектов и детальную страницу одного объекта из базы данных.
18.	Создать форму добавления или редактирования данных; обработать GET- и POST-запросы.
19.	Добавить базовую серверную валидацию формы и понятные сообщения об ошибках.
20.	Зарегистрировать модели в Django admin и настроить удобное отображение списка (например, list_display, search_fields или list_filter).
21.	Подключить media-файлы и реализовать загрузку изображения/обложки или другого пользовательского файла.
22.	Реализовать минимум одну CRUD-операцию помимо чтения: создание, редактирование или удаление записи.
Результат модуля
•	Полноценное приложение с постоянным хранением данных через Django ORM.
•	Работающие формы и GET/POST-обработка.
•	Настроенная admin-панель и поддержка media-файлов.
Что сдаёт студент
•	Исходный код/репозиторий с миграциями.
•	Краткую схему моделей или описание связей между ними.
•	Скриншоты: список данных, форма, admin-панель, пример media-файла.
Минимальная проверка работоспособности
•	После миграций проект запускается на чистой среде.
•	Форма действительно изменяет данные в базе.
•	Данные, добавленные через admin или форму, отображаются на сайте.
•	Media-файлы открываются корректно в режиме разработки.
Модуль 4. Итоговый mini-project: онлайн-библиотека + API
Период: недели 13–15. Цель — объединить результаты всех предыдущих модулей в завершённый web-проект и добавить программный интерфейс API.
Что необходимо выполнить
23.	Довести проект до законченного пользовательского сценария: главная страница → каталог → детальная страница → добавление/изменение данных.
24.	Добавить поиск, фильтрацию или сортировку данных минимум по одному параметру.
25.	Создать API минимум для одной сущности проекта. API должен возвращать структурированные данные (JSON) для списка и/или отдельного объекта.
26.	Добавить обработку некорректных запросов и базовую проверку входных данных.
27.	Проверить основные страницы, формы, модели, admin, static/media и API; устранить критические ошибки.
28.	Оформить README: назначение проекта, стек технологий, установка, запуск, основные URL, структура API, примеры использования.
29.	Подготовить демонстрацию проекта продолжительностью 5–7 минут: проблема/идея, архитектура, интерфейс, база данных, форма, admin, API.
30.	При использовании LLM/AI указать в README, для каких задач он применялся (идея, код, тестирование, документация) и какие части были проверены/изменены студентом самостоятельно.
Результат модуля
•	Итоговый Django web-проект с интерфейсом, серверной логикой, базой данных и API.
•	Связанный и демонстрируемый пользовательский сценарий.
•	Документированный проект, который можно запустить по инструкции.
Что сдаёт студент
•	Полный исходный код или ссылку на Git-репозиторий.
•	README.md с инструкцией запуска и описанием API.
•	Короткое видео/презентацию или очную защиту по требованиям преподавателя.
•	Файл requirements.txt (или эквивалентный список зависимостей).
Минимальная проверка работоспособности
•	Проект запускается без критических ошибок.
•	Основной пользовательский сценарий проходит от начала до конца.
•	API возвращает корректный JSON и соответствует описанию в README.
•	Нет битых ссылок на static/media; формы и база данных работают после перезапуска сервера.
